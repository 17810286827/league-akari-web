# 图标本地化策略：小体积全量镜像 + 本地优先多级降级

前端所有游戏图标（英雄头像、装备、召唤师技能、符文、海克斯强化）此前直连外部 CDN
（raw.communitydragon.org / ddragon / game.gtimg.cn），国内访问慢且不稳定，首屏几十个
小图标并发拉取是首次加载慢的根因（浏览器 HTTP 缓存已生效，仅首次慢）。决定把游戏图标
全量本地化到自有服务器：同步脚本（`npm run sync:icons`，手动触发，游戏版本更新后跑
一次）从 CDragon/DDragon/gtimg 批量拉取到 `public/icons/`（实测 1890 个图标共 25MB：
英雄 236 张 6.7MB、装备 867 张 7.3MB、海克斯 643 张 8.2MB、技能 36 张、符文 103 张、
样式 5 张）；图标目录不进 git，Docker 构建期执行脚本注入（独立构建层 + layer cache，
日常构建不重复下载）。运行时本地路径优先、原 CDN 链接兜底——复用 CdnImage 的失败重试
机制，本地缺图（新英雄尚未同步）时用户无感降级，无需清单文件。

> 事实修正（2026-09-08 实施时）：初版 ADR 按"装备 3000+ 张约 30MB"的估算把装备排除在
> 本地化外。实测 CDragon items.json 全量仅 867 件（ADR 0003 亦有记载）、7.3MB，
> 与英雄/海克斯合计全量 25MB——体积顾虑不成立，装备已一并本地化，其降级链升级为
> 本地 → DDragon → CDragon 三级（与 ADR 0003 双源策略叠加）。仍排除在外的只有
> 召唤师头像（数千张且随版本增长，单页面仅出现 1 枚，收益不成比例）。

## Status

accepted

## Considered Options

- **装备排除在本地化外（初版决策）** → 修正——基于 3000 张 30MB 的错误估算；实测
  867 张 7.3MB，与全量合计 25MB，体积可控
- **按需子集（只拉车队实际用过的英雄/装备）** → 否决——需要维护动态清单，新增英雄
  时首次仍走慢速 CDN，且清单逻辑引入额外维护成本
- **Service Worker 浏览器缓存** → 否决——对首次加载（真正的痛点）无帮助，且自有
  服务器形态下构建期镜像方案更简单直接
- **后端图片代理 + 强缓存头** → 否决——Java 后端与前端分仓部署，为其增加图片代理
  职责跨了上下文边界；nginx 直出静态文件更简单
- **选定全量镜像 + 本地优先**：同步一次 25MB、Docker 构建期完成、本地缺图自动回退
  CDN，维护成本最低

## Consequences

- `CdnImage` 的 `fallback` 单兜底属性升级为多级降级链 `sources`（源数组，逐级回退
  直到占位符）；装备为三级链（本地 → DDragon → CDragon，衔接 ADR 0003），
  英雄/技能/符文/海克斯为二级链（本地 → CDragon/gtimg）；无链时行为同旧版
- `icon-url.ts` / `game-resource.ts` 的各 DisplayResource 携带 `iconSources` 降级链，
  既有单 URL 字段保持不变（旧消费方零改动）
- 同步脚本的「清单 → 下载计划」为纯函数（`scripts/icon-sync/plan.ts`，有测试），
  复用运行时同一套 URL 构造函数——两侧约定失配会立即表现为本地永远缺图
- 绕过 CdnImage 的裸 `<img>`（侧边栏英雄筛选、回放面板、诊断面板、赛季报告、榜单页）
  统一收口到 CdnImage，顺带获得懒加载与占位符
- `public/icons/` 加入 `.gitignore`；新游戏版本上线后需手动跑一次同步脚本，
  否则新增图标会静默走 CDN 兜底（功能不缺失，仅该图标首次加载慢）
- nginx 为 `/icons/` 增加 30 天 immutable 缓存头（图标内容不可变，版本更新即换文件）
- 召唤师头像 `profileIconUrl` 仍走 DDragon 单源（排除在本地化外，仅顶栏 1 枚）
